# 每日免费模拟：设备当地零点刷新

状态：用户于 2026-11-22 最终指定匿名浏览器、设备系统时区当地零点刷新，覆盖此前 UTC 选择。用户不要求单独的夏令时功能或专项测试；采用原生 Intl 时区数据，不维护额外规则。

## 产品与边界

每个匿名浏览器每日可免费进行一次完整模拟，无需账号。设备提供 IANA 时区，服务器提供时钟并控制资格；清除 Cookie 或换设备仍可能形成新身份，不宣称自然人级限制。首次成功占用当地当天资格，未使用资格不累积。继续昨日已开始的模拟不占今天的新资格；已开始的一次模拟最多 10 次尝试，不因跨日增加。首次成功前失败也计入每天最多 10 次尝试，次日恢复。

删除、放弃或过期不返还当日已使用资格。进行中的存档不会自动删除。完成后再次开始先查询服务端；展示新设置，明确告知替换旧服务端数值记录，用户提交后才按旧 ID 原子替换；用稳定创建请求 ID 处理丢失响应和并发重试，只有旧 ID、请求 ID 与设置匹配才返回同一草稿。取消返回旧模拟；本地旧文本保留可导出。仍有进行中的模拟时沿用明确确认的删除入口。

系统时区变化在当前计额周期结束后生效，避免通过调时区立即领取第二次。服务器返回实际计额时区和下次资格时间，页面显示本地午夜规则及实际下次可用时间，并在到期、恢复可见或手动刷新时重新查询服务端。无法检测时区的旧客户端使用 UTC，既有 API 字段兼容。

全站生产 300 次/UTC 日、预览零预算、真实模型测试需另行授权、30 天数值留存保持。匿名额度元数据保留最长 180 天，自最近配额更新或首次成功计时；不新增服务、依赖、账户、支付或遥测。

## 方案与取舍

曾比较匿名浏览器固定 UTC、固定北京时间、账号三种方案；用户最终选择设备当地时间。最小方案沿用单存档结构和 sessions 配额，在数据库增加尝试周期、时区、锁定边界与已用资格到期时间。单独记录资格到期，避免更换时区后把旧成功误判为新一天使用。无需新增配额表或定时重置任务，请求时按服务器时间判断。

第一性原理：把新模拟资格、进行中模拟尝试、全站预算三个生命周期分开。并发资格判断与写入必须在 D1 同一事务中；模型调用仍在事务外、单次、不自动重试。

## 验证与发布

真实本地 D1 覆盖 UTC 作为一个时区、上海/加德满都当地午夜、切换时区、首个成功跨午夜、继续旧模拟、失败耗尽和次日恢复、删除、并发替换、过期租约、迁移旧数据。浏览器 fixture 验证新一天入口、取消、替换失败恢复、双语说明，并明确不把 fixture 当真实模型证据。全套本机检查、built runtime、15 页/公开资源和移动端检查后独立审阅，按持续授权提交、推送、发布、正式站读回。

对抗审查：若必须识别同一个自然人，匿名方案应放弃并重新定义身份要求；若跨日增加已开始模拟的尝试或破坏存档，需修改生命周期边界；若 SQL 零行、迁移或并发放出重复资格，需修改原子守卫。结论：存活，以回归和独立审阅为发布门槛。
