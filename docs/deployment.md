## Isolated preview configuration

`env.preview` names `goodbye-startup-preview` with its own D1, rate-limit namespace and workers.dev origin. It has no production routes, uses `X-Robots-Tag: noindex, nofollow` for HTML and preview static assets, and leaves AI budget at zero. The preview D1 was created under the authorized scope; the top-level default database ID remains a nondeployable placeholder. The explicit `production` environment has its own real D1 binding and a 300-call daily cap.

Select the environment at **build time**, then deploy the generated config; passing `--env` after building the default app does not select the right Vite environment:

```sh
CLOUDFLARE_ENV=preview npm run build
npx wrangler deploy --config dist/server/wrangler.json --dry-run
# After provisioning, migrations, secrets, permission and budget checks:
npx wrangler deploy --config dist/server/wrangler.json
```

Secret commands and migrations against the source configuration use `--config wrangler.jsonc --env preview`. Verify the generated config names `goodbye-startup-preview`, has the preview DB ID and no production routes before deployment. Do not leave a positive daily budget enabled after a finite evaluation: it resets daily and is not the lifetime 20-request authorization.

## Environment contract

| Binding/variable      | Purpose                                     | Default / rule                                                             |
| --------------------- | ------------------------------------------- | -------------------------------------------------------------------------- |
| `DB`                  | D1 numerical state and quota                | Required; default is a placeholder, preview/production have isolated IDs   |
| `SESSION_SECRET`      | HMAC signing and identifier separation      | Secret, at least 32 random bytes; never a public variable                  |
| `DEEPSEEK_API_KEY`    | Provider authorization                      | Secret, needed for real inference                                          |
| `DEEPSEEK_MODEL`      | Server-selected model                       | `deepseek-flash`, verify account support during explicit evaluation        |
| `AI_MODE`             | Provider or local fixture                   | `deepseek` in committed production config                                  |
| `APP_ENV`             | Runtime mode                                | `production`; local mock additionally requires a loopback request hostname |
| `AI_DAILY_CALL_LIMIT` | Global attempted-call cap                   | `0` fails closed; choose a deliberate approved positive limit              |
| `AI_RATE_LIMITER`     | Approximate per-location short-window guard | 6/minute per HMAC IP/action key in production                              |
| `SITE_ORIGIN`         | Exact mutation origin                       | `https://goodbye.help`; configure preview hostname when testing            |
| `ASSETS`              | Built public assets                         | Generated by Cloudflare Vite plugin                                        |

Keep `compatibility_date=2025-09-01` and `nodejs_compat` until separately regression-tested. Provider and session secrets use Wrangler secret commands or the dashboard; never put them in JSON config, shell history or command arguments. Pages secrets cannot be read back or exported to a new Worker. Supply the secret from its owner’s existing private source.

1. Run `npm ci`, local setup/migration, `npm run check`, browser tests, public-page audit and Worker smoke. Confirm local fixture mode so checks do not spend provider credits.
2. Review git diff, dependency overrides, D1 schema and privacy/copy changes. Keep the original Pages deployment available.
3. After authorization, provision a preview D1 database and a separate Worker. Put its ID in an environment-specific Wrangler configuration. `wrangler d1 create` and remote migrations create external state; the isolated preview was provisioned under the 2026-11-09 authorization. Inspect plan quotas/costs before creating any further environment.
4. Set secrets via `npx wrangler secret put SESSION_SECRET` and `DEEPSEEK_API_KEY` for that Worker. Set preview origin, real model and a small approved daily cap. Do not reuse production D1 for browser tests.
5. Apply `npx wrangler d1 migrations apply DB --remote` using the reviewed preview config. Build, then deploy its generated `dist/server/wrangler.json`. The `deploy` script targets that generated configuration and is not automatic CI.
6. On preview, verify cookie Secure/HttpOnly/SameSite, origin enforcement, D1 bindings, rate limiting, daily cap, scheduled purge, assets, all 15 routes and metadata. Perform a small, explicitly authorized real-provider evaluation from `ai-evaluation.md`. Passing mock tests does not prove model quality or provider/model availability.
7. Review domain cutover separately. For the initial migration, the domain was attached to Pages and required a reviewed transfer before binding the Worker custom domain. It is now attached to the production Worker; do not repeat the initial detach steps for routine releases. Preserve `www` → apex and `startup.goodbye.help` → `/simulator` redirects. Do not touch `wise.goodbye.help` (separate payment callback service).
8. After cutover, read back live HTML/headers/RSS/robots/sitemap and verify real user flow. Review logs by request ID/code, never text. Confirm the scheduled retention purge executes.

## Rollback and recovery

- Application rollback: route traffic back to the retained Pages deployment, or deploy the last verified Worker version with its compatible schema. Existing new-run D1 records remain isolated; old Pages cannot interpret them.
- Data recovery: D1 recovery capabilities depend on the account plan and configured retention. Check current official D1 backup/Time Travel documentation before release. A database rollback can replay quota/state history; stop writes and reconcile before reopening.
- Never down-migrate production tables destructively as part of a code rollback. Future migrations must be additive or have a separately reviewed recovery procedure.
- Session-secret rotation invalidates anonymous cookies; it can effectively create fresh anonymous allocations. Treat this as an operational event, not a transparent rotation.
- Local reset: use a separate test DB/state directory or explicitly remove only local `.wrangler/state` when no valuable local saves are needed. Do not suggest a blanket `git clean -fdx`.

Official references: [Workers deployment](https://developers.cloudflare.com/workers/wrangler/commands/), [D1 migrations](https://developers.cloudflare.com/d1/reference/migrations/), [D1 recovery](https://developers.cloudflare.com/d1/reference/time-travel/). GSC, DNS and deployment authorizations are separate.

## Production releases via local Wrangler

GitHub stores code only. Repository Actions are disabled and all workflow files have been removed: no GitHub test runner, build or deployment is used. Legacy Pages Git builds are also disabled. Run testing, building and publishing locally; pushing main does not deploy. Use the existing authorized local Cloudflare token; no new CI token or Actions secret is needed. Its allowed IPv4 path is selected with `NODE_OPTIONS='--dns-result-order=ipv4first --no-network-family-autoselection'`; do not remove IP restrictions or broaden scopes to make a deployment work.

Release only a clean, reviewed main revision after local checks pass. Confirm local HEAD equals remote main and record that SHA with the resulting Worker version. Build the explicit production environment; never deploy a default or preview artifact to production:

```sh
npm run check
npm run test:e2e
CLOUDFLARE_ENV=production npm run build
node scripts/check-deploy-config.mjs
npm run secrets:check
npx wrangler d1 migrations apply DB --remote --env production
npx wrangler deploy --config dist/server/wrangler.json
TEST_BASE_URL=https://goodbye.help node scripts/audit-pages.ts
TEST_BASE_URL=https://goodbye.help node scripts/check-live.mjs
```

The live check uses health/session reads and invalid setup requests, never model inference. Production permits 300 attempted model calls per UTC day; failed provider attempts also count. Preview remains at zero. The separate six-call release acceptance allowance was fully consumed and is tracked in a private durable ledger; those six also counted toward that day's production cap. Do not reopen finite evaluation budgets without authorization.

The initial candidate was staged at a temporary workers.dev endpoint, then the verified main version was activated with `wrangler versions upload` and `wrangler versions deploy`. Only the apex Pages CNAME/domain attachment was removed, followed by `wrangler triggers deploy` to bind the production custom domain and cron. Final `env.production.routes` binds only the apex, and workers.dev/version previews are disabled. Routine releases can use the deploy command above without detaching the domain again. Existing www/startup redirects and unrelated DNS records were verified unchanged.
